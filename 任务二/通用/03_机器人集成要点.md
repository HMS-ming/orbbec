# 机器人集成要点

> 位置：任务二 / 通用（平台无关）
>
> 前置：已读 [通用 02 话题与坐标系](02_话题与坐标系.md)，理解相机节点输出的话题与坐标系
>
> 相关：[Ubuntu平台 / 02 启动与查看数据流](../Ubuntu平台/02_启动与查看数据流.md)
>
> 本步目标：把相机接入机器人的机体坐标系，针对感知任务选择数据形态并规划资源占用
>
> 示例环境：示例设备 **Astra 2**，驱动 **OrbbecSDK ROS2 Wrapper v2.10.6**，**ROS 2 Jazzy**

## 0. 结论

✅ 接入机器人的三个要点：**发布机体到相机的静态 TF**、**按任务选择点云或图像的深度形态**、**控制分辨率与流数以约束 CPU 与带宽占用**。

## 1. 机体到相机的静态变换

相机节点发布的根坐标系是 `camera_depth_frame`，它对应**相机外壳的几何原点**。要让机器人其他节点能用这份数据，必须从机体 `base_link` 补一条静态变换直接指向它：

```bash
ros2 run tf2_ros static_transform_publisher \
  --frame-id base_link --child-frame-id camera_depth_frame \
  --x 0.15 --y 0.0 --z 0.08 --qx 0 --qy 0 --qz 0 --qw 1
```

若机器人已有 URDF 模型，也可以把相机作为一个固定连接的部件写进模型，再让模型的相机基座与 `camera_depth_frame` 对齐：

```xml
<link name="camera_link"/>
<joint name="camera_joint" type="fixed">
  <parent link="base_link"/>
  <child link="camera_link"/>
  <origin xyz="0.15 0 0.08" rpy="0 0 0"/>
</joint>
```

使用 `orbbec_description` 包中的型号模型（Astra 2 对应 `urdf/astra_2.urdf.xacro`）时，模型的根坐标系为 `camera_link`，其下已包含与驱动一致的 `camera_depth_frame`、`camera_color_frame` 等坐标系。只需把 `camera_link` 固定连接到机体即可，无需再补内部变换。

⚠️ 平移与旋转取值对应相机的**实际安装位置与朝向**，务必量测后填入，否则点云在机体坐标系中会整体偏移。

### 深度图与彩色图的帧对齐

深度流与彩色流属于不同的光学坐标系，两者之间有固定的外参。若要直接读取彩色图与深度图同一像素位置，可在启动时开启深度到彩色的对齐（参数 `depth_registration`、`align_mode`、`enable_d2c_viewer`，见 [Ubuntu平台 / 02](../Ubuntu平台/02_启动与查看数据流.md)）。对齐后图像与点云使用彩色相机坐标系。

在不对齐的情况下，**深度图与彩色图按同样的像素坐标读取时，不指向同一空间点**。

## 2. 数据形态选择

| 任务 | 首选数据 | 原因 |
|---|---|---|
| 避障、距离检测 | 深度图直接订阅，或 `depth/points` 点云 | 点云更直观、可在 RViz2 直接看，但更耗带宽 |
| 目标检测、语义分割 | 彩色图 | 颜色与纹理信息完整 |
| 建图、抓取、位姿估计 | 点云 `depth/points` 或彩色点云 | 需要三维几何 |
| 暗光环境成像 | 红外图 | 红外指令存在时适用 |

**点云是按需生成**的：默认 `enable_point_cloud:=true`，若机器人自研节点不需要三维点，可关闭以节省 CPU 与带宽：

```bash
ros2 launch orbbec_camera astra2.launch.py enable_point_cloud:=false
```

**彩色点云**（深度注册到彩色帧）由 `enable_colored_point_cloud:=true` 控制，生成开销高于普通点云，仅在确实需要带颜色点云时开启。

## 3. 分辨率、帧率与带宽

相机按启动参数输出指定分辨率与帧率。分辨率与帧率越高，占用的 USB 带宽、主机 CPU（解码、点云生成）与发布带宽越大。按算力调节的主要参数：

| 参数 | 作用 |
|---|---|
| `depth_width` / `depth_height` / `depth_fps` | 深度流分辨率与帧率 |
| `color_width` / `color_height` / `color_fps` | 彩色流分辨率与帧率 |
| `ir_width` / `ir_height` / `ir_fps` | 红外流分辨率与帧率 |
| `enable_depth` / `enable_color` / `enable_ir` | 关闭不需要的流 |
| `color_format` | `MJPG`（默认，省带宽）或 `YUYV` / `RGB` |
| `enable_point_cloud` | 关闭点云生成 |

示例：嵌入式主机上只保留避障所需的深度流，降低分辨率：

```bash
ros2 launch orbbec_camera astra2.launch.py \
  enable_color:=false enable_ir:=false \
  depth_width:=400 depth_height:=300 depth_fps:=15
```

⚠️ 流的分辨率与帧率必须在 `list_camera_profile_mode_node` 列出的组合内取值，否则节点启动失败。查询该产品支持的所有流组合：

```bash
ros2 run orbbec_camera list_camera_profile_mode_node
```

## 4. 其它机器人相关参数

| 参数 | 取值 / 作用 |
|---|---|
| `camera_name` | 命名空间；多相机时改为各自独立命名，避免话题冲突 |
| `serial_number` | 多相机时指定具体设备；单相机可留空 |
| `usb_port` | 多相机时指定设备所在 USB 端口 |
| `time_domain` | `global` 用系统时间戳，`device` 用设备时间戳 |
| `enable_frame_sync` | 深度与彩色帧同步；同版本下按启动文件默认即可 |
| `publish_tf` | 是否发布相机内部 TF（默认开启） |

多相机场景的参数组织方式，见 [驱动文档](https://orbbec.github.io/OrbbecSDK_ROS2/) 的多相机章节。

## 5. 机器人开发流程建议

1. **先在主机确认出图**：跑通 [Ubuntu平台 / 02](../Ubuntu平台/02_启动与查看数据流.md) 的 RViz2 查看流程，确认相机本身正常。
2. **再接到机器人**：把相机装到机器人、量测安装位姿，写入 URDF 静态变换。
3. **调资源**：用 `ros2 topic hz` 观察实际帧率，用 `ros2 topic bw` 观察带宽，必要时降分辨率、关点云。
4. **写感知节点**：订阅所需话题，按 [通用 02](02_话题与坐标系.md) 的编码与坐标系说明取数。
5. **录制回归**：用 `ros2 bag record` 录制一份数据，便于不接相机时离线调试与回放。
