# 在机器人中接入深度相机：通用接入方案

> 位置：任务二 / 通用（平台无关）
>
> 前置：已在主机上安装 Ubuntu 与 ROS 2；深度相机的基本概念见 [任务一 / 通用 01 产品准备](../../任务一/通用/01_产品准备.md)
>
> 相关：[Ubuntu平台 / 01 环境准备与驱动安装](../Ubuntu平台/01_环境准备与驱动安装.md) · [Ubuntu平台 / 02 启动与查看数据流](../Ubuntu平台/02_启动与查看数据流.md)
>
> 本步目标：确定接入方式、驱动版本与型号对应的启动文件，了解整条数据链路构成
>
> 示例环境：示例设备 **Astra 2**，驱动 **OrbbecSDK ROS2 Wrapper v2.10.6**，**ROS 2 Jazzy**

## 0. 结论

✅ 深度相机接入 ROS 2 的方式是使用 **OrbbecSDK ROS2 Wrapper**：它把 SDK 的取流能力封装成一个相机节点，按标准 ROS 2 消息发布图像、点云、IMU 与相机内参，机器人其余节点只需订阅话题。

✅ ROS 2 驱动与独立 SDK 是两个**独立发行物**。驱动包内已自带 SDK 运行库，按任务一安装过独立 SDK 的主机无需卸载，两者可以共存，但**版本应保持一致**。

## 1. 接入后的数据形态

相机节点启动后，数据以话题形式输出，各类数据分别对应不同的上层用途：

| 数据 | 话题（默认命名空间 `/camera`） | 消息类型 | 典型用途 |
|---|---|---|---|
| 深度图 | `/camera/depth/image_raw` | `sensor_msgs/msg/Image` | 距离测量、避障、地面检测 |
| 彩色图 | `/camera/color/image_raw` | `sensor_msgs/msg/Image` | 目标识别、可视化 |
| 红外图 | `/camera/ir/image_raw` | `sensor_msgs/msg/Image` | 暗光成像、结构光散斑调试 |
| 点云 | `/camera/depth/points` | `sensor_msgs/msg/PointCloud2` | 三维感知、建图、抓取定位 |
| IMU | `/camera/gyro_accel/sample` | `sensor_msgs/msg/Imu` | 运动估计、与视觉融合（仅具备 IMU 的型号有数据，见通用 02） |
| 相机内参 | `/camera/depth/camera_info` | `sensor_msgs/msg/CameraInfo` | 像素与三维坐标互相换算 |

完整话题清单、编码格式与坐标系定义见 [通用 02 话题与坐标系](02_话题与坐标系.md)。

## 2. 版本与发行版对应关系

驱动通过 GitHub Releases 发布**预编译 deb 包**，每个 zip 对应「一种 ROS 2 发行版 + 一种主机架构」：

| 项目 | 取值 | 说明 |
|---|---|---|
| ROS 2 发行版 | Humble / Jazzy / Lyrical | 发行包覆盖这三种；Foxy 与 Rolling 需从源码构建 |
| 主机架构 | `amd64` / `arm64` | 由主机决定，与相机型号无关 |

发布页的文件名为 `orbbec-ros2-debs-<发行版>-<架构>.zip`，解压后得到两个 deb：

```text
ros-<发行版>-orbbec-camera-msgs_<版本>_<架构>.deb   消息与服务定义
ros-<发行版>-orbbec-camera_<版本>_<架构>.deb        相机节点本身
```

⚠️ 驱动版本应与任务一所用 SDK 版本对应（示例环境两者均为 v2.10.6）。主机上若已有版本不一致的独立 SDK，`/usr/local/lib` 下的库可能先于驱动自带的库被加载。

## 3. 型号与启动文件

每种型号对应一个启动文件，参数默认值按该型号的传感器能力设定。启动文件随 `orbbec_camera` 包安装，位于 `share/orbbec_camera/launch/`。

| 型号系列 | 启动文件 |
|---|---|
| Astra 2 | `astra2.launch.py` |
| Astra Mini Pro / Astra Mini S Pro | `astra.launch.py` |
| Gemini 2 / Gemini 2 L | `gemini2.launch.py` / `gemini2L.launch.py` |
| Gemini 210 / 215 | `gemini210.launch.py` |
| Gemini 301 系列（305 / 305g） | `gemini_301_series.launch.py` |
| Gemini 330 系列 | `gemini_330_series.launch.py` |
| Gemini 340 系列 | `gemini345.launch.py` / `gemini345_lg.launch.py` |
| Gemini 430 系列 | `gemini435_le.launch.py` |
| Femto Bolt | `femto_bolt.launch.py` |
| Femto Mega / Femto Mega I | `femto_mega.launch.py` |
| DaBai 系列 | `dabai_a.launch.py` 等对应型号文件 |
| LiDAR 系列 | `lidar.launch.py` |

示例环境（Astra 2）使用 `astra2.launch.py`。型号不在上表时，可在 `share/orbbec_camera/launch/` 目录中按型号名查找。

## 4. 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Ubuntu；x64 平台已验证 Ubuntu 22.04 |
| ROS 2 | 已安装且能 `source` 对应发行版的 `setup.bash` |
| 架构 | `amd64` 或 `arm64` |
| 磁盘 | 驱动与依赖约占数百 MB |
| 权限 | 不需要 `sudo` 运行节点（由 udev 规则授予设备访问权限） |

⚠️ **ARM64 的支持范围**：受支持的 ARM64 平台为 NVIDIA Jetson 系列。其他 ARM64 平台在架构上可以安装 `arm64` 包，但不在受支持平台列表内，兼容性需自行验证。

## 5. 接入做到哪一步

接入深度相机不是只有「装上驱动」一件事，按目标选择对应章节：

| 目标 | 需要做的 | 章节 |
|---|---|---|
| 在 RViz2 中看到深度图与点云 | 安装驱动并启动节点 | Ubuntu 01 · Ubuntu 02 |
| 在自研节点中订阅图像或点云 | 了解话题、编码、QoS、坐标系 | 通用 02 |
| 装到机器人上并与机体坐标系对齐 | 配置 TF 挂载与相机外参 | 通用 03 |
| 多相机、降载、时间同步 | 参数与资源规划 | 通用 03 |
